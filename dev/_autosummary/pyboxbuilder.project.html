    pyboxbuilder.project¶

    Project class — top-level API entry point.

    One build path. Project.build() resolves the layout and builds every body, lid and spacer. Project.show() renders what it returns and Project.export() writes what it returns; neither builds geometry of its own. That is the whole difference between the two — render or write — and it is structural rather than a convention, because the alternative was two copies of the build that drifted: the exported parts silently lost their rounding, their per-side wall tops and their interior masks while the preview kept all three.

    class pyboxbuilder.project.Piece(label: str, kind: str, size: tuple[float, float, float], position: tuple[float, float, float], _build: collections.abc.Callable[[], Any | None], builder: BoxBuilder | None = None)[source]¶

    Bases: object

    One printable piece of a project.

    Both Project.show() and Project.export() consume these, so a piece previewed and the same piece printed are the same solid.

    The geometry is built on demand. Everything that identifies a piece — its label, its size, where it sits, and the description it would be built from — is known without building it, and that is what decides whether an export needs to write it at all (FR-031). Building eagerly meant a re-export with nothing changed still paid for every box: 15 of Emberleaf’s 21 seconds at draft precision, and minutes at the 256 facets an export actually uses, all spent on geometry the fingerprint was about to discard.

    arrange(layout, origin: tuple[float, float, float] = (0.0, 0.0, 0.0))[source]¶

    Position boxes from a declarative layout tree (T186).

    The alternative to hand-typed coordinates for densely packed inserts, where the packer cannot help: describe the structure with columns/rows/stack and let the sizes decide the positions.

    A box placed here is placed, so it is neither expanded nor rotated by the packer — the arrangement’s arithmetic assumed the size it was given (FR-013c).

    Parameters:¶
    layout¶

    A pyboxbuilder.layout group, or a single box label.

    origin: tuple[float, float, float] = (0.0, 0.0, 0.0)¶

    Where the arrangement’s minimum corner goes.

    Returns:¶

    The Arrangement, so a caller can inspect the resolved extent.

    Raises:¶

    • LayoutError – If the tree names an unknown box or places one twice.

    • ValueError – If a named box has no explicit size, or the arrangement does not fit the game box.

    build() → Build[source]¶

    Resolve the layout and describe every piece of this project.

    The one build path. show() renders what this returns and export() writes it, so a previewed part and a printed part are the same solid — there is no second assembly of the geometry for one of them to fall behind in.

    Resolving the layout is eager, because every piece’s size and position depend on every other’s. The geometry is built per piece on first use (Piece.solid), so a caller that only needs some of it — an export skipping the boxes whose description has not changed, a preview of one box — pays for what it asks for.

    Returns:¶

    A Build carrying every body, lid and spacer, each with the position it occupies in the game box.

    Raises:¶

    • ValueError – If a box can be sized neither explicitly nor from its compartments, if its compartments overflow its interior, or if its compartment ratios overflow.

    • PackingError – If the boxes cannot be packed into the game box.

    export(out_dir: str | Path, fn: int | None = None, fa: float | None = None, fs: float | None = None, only: str | Iterable[str] | None = None, force: bool = False) → ExportResult[source]¶

    Write every piece of this project, and the layout PDF.

    Writes exactly what show() renders — the same build() — so the only difference between previewing and exporting is that this one puts the result on disk.

    A box whose description has not changed is not rebuilt. The digest that decides whether a file needs writing (FR-031) is known before any geometry is cut, so an unchanged box costs nothing at all rather than being built and then discarded. That is what makes a repeat export at print precision practical: it is the difference between minutes and a second.

    Parameters:¶
    out_dir: str | Path¶

    Directory to write into; files land under {out_dir}/{project name}/mmu/ and .../single/.

    fn: int | None = None¶

    Fixed facets per circle for every curve in the exported geometry. None (the default) uses EXPORT_FN — an export is what gets printed, so it is built at full precision. Pass a smaller value for a quick throwaway build.

    fa: float | None = None¶

    Minimum angle per fragment, in degrees (default 12).

    fs: float | None = None¶

    Minimum fragment size, in mm (default 2).

    only: str | Iterable[str] | None = None¶

    Export just these box labels. Everything else is left alone on disk — not deleted, not rewritten.

    force: bool = False¶

    Rebuild and rewrite every piece, whether its description changed or not.

    Returns:¶

    An ExportResult listing the files written and skipped.

    Raises:¶

    • ValueError – If a box cannot be sized, a precision setting is out of range, or only names a box this project does not have.

    • PackingError – If the boxes cannot be packed into the game box.

    Build the list of separately-coloured solids show() renders.

    Public because it is the cheap way to exercise the geometry: it packs the layout and builds every body, lid and spacer, but writes nothing and needs no render binary. A CI pass wants exactly that — the build path without the printable output — where export() would spend its time tessellating 3MFs no one is going to print.

    show(show_lids: bool = False, remove_layers: int = 0, only: str | Iterable[str] | None = None, lids_only: bool = False, fn: int | None = None, fa: float | None = None, fs: float | None = None) → None[source]¶

    Preview the packed box layout interactively.

    Renders exactly what export() writes — same build, same geometry — as separate solids at their packed positions. Each box is shown as its own solid, because a union carries one colour and would fuse touching boxes into an indivisible blob, hiding the seams a packing preview exists to show.

    Writes no files, and generates no layout PDF.

    Parameters:¶
    show_lids: bool = False¶

    Place each lid in its seated position as well. Off by default because lids cover the compartments and their neighbours. A shown lid carries its decoration and is drawn semi-transparent in a lighter shade of its box’s colour so it reads as a separate piece.

    remove_layers: int = 0¶

    Omit the top N vertical layers of the packed layout, revealing what sits underneath — the live equivalent of the exploded PDF view. A box is removed when its top surface rises above the cut.

    only: str | Iterable[str] | None = None¶

    Show just these boxes, by label. One box on its own is the usual way to look at a box you are working on, and it is also the cheap one: nothing else is built.

    lids_only: bool = False¶

    Show the lids without their bodies — for looking at a label or a lid pattern, which the body would otherwise sit under. Implies show_lids.

    fn: int | None = None¶

    Fixed facets per circle for every curve in the preview. None (the default) defers to fa/fs, which sizes facets by how large each curve actually is — that is what keeps a preview responsive. Unlike export(), this does not jump to export precision.

    fa: float | None = None¶

    Minimum angle per fragment, in degrees (default 12).

    fs: float | None = None¶

    Minimum fragment size, in mm (default 2).

    Raises:¶

    ValueError – If remove_layers is negative, only names a box this project does not have, or a precision setting is out of range.

    board_thickness : float = 0.0¶

    Thickness of the game board (mm).

    Reserved at the TOP of the box: the board sits on top of the sub-boxes and is the first thing out, so this is not a spacer gap.

    box_defaults : dict | None = None¶

    Defaults applied to every box() call that does not say otherwise.

    Every keyword box() accepts may be given here once instead of on each box — wall_thickness, no_rotate, color and the rest. An insert whose boxes all share a wall thickness or all decline rotation says so once (FR-000b):

    Project("Earth", ..., box_defaults={"wall_thickness": 3.0})

    A value passed to box() always wins over the default.

    clearance_slack : float = 1.0¶

    Clearance slack on each side of the game box in the X/Y directions (mm).

    floor_thickness : float = 1.6¶

    Default floor thickness.

    game_box_size : tuple[float, float, float] | None = None¶

    Outer game box dimensions [W, L, H] in mm. None = standalone boxes (no game box).

    gap_threshold : float = 10.0¶

    Gaps <= this are absorbed by adjacent boxes.

    generate_spacers : bool = True¶

    Whether to automatically generate spacer boxes/trays to fill layout gaps.

    inner_rounding : float | None = None¶

    Edge radius where a partial lid grips the body (FR-044b).

    Applies to a cap’s band and skirt cavity, and a slipover’s body and sleeve cavity — both halves of the grip, so they nest. None derives it as half the outer radius.

    lid_thickness : float = 2.0¶

    Default lid thickness.

    min_spacer_dim : float = 15.0¶

    Minimum spacer width/length before absorption.

    min_spacer_height : float = 5.0¶

    A spacer tray thinner than this on any axis is dropped as unprintable (FR-014).

    name : str¶

    Game name; becomes the output subdirectory.

    piece_bounds : tuple¶

    Bounding box of every exported piece, populated by export() (FR-027).

    rounding : float | None = None¶

    Edge radius for every box’s exposed edges (FR-043/FR-044).

    None derives it per box as wall_thickness / 2. 0 leaves every edge square.

    wall_thickness : float = 2.0¶

    Default wall thickness for all sub-boxes.
